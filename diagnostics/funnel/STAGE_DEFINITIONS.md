## 1. THE CENTRAL CORRECTION — "142 → 3" is not one funnel

**142 counts tables. 3 counts claims.** They are different populations in different units, and
no item ever travels from the first to the second. There is no set of "139 removed grid
returns", and no conservation law connects them. The brief's framing is a category error, and
the report states it rather than manufacturing a chain to satisfy it.

What actually exists is two funnels that meet only at one place — the cells produced by funnel A
are an *input* to one decision inside funnel B:

```
FUNNEL A (tables)                        FUNNEL B (claims)
160 table blocks                         22 evidence items
  → 142 backend grid returns               → 14 reach structural_bind
  → 92 cell tables                         → 0 bound
  → 2187 attached cells  ──────────────────┘ (cells are the binder's candidate pool)
                                           → 3 RETURNED metrics
```

The 3 RETURNED and the 0 bound are **not** downstream of the 2187 cells in any counting sense.
Section 6 of the report shows the 3 RETURNED never touch the binder at all.

## 2. FUNNEL A — tables. Operational definitions

All line numbers are `src/evidence/represent_layout.py` unless stated.

### A1. `table_block`

**One item:** one block emitted by `represent.blocks_from_pdf` whose `block_type == "table"`
(selected at line 318).
**Enters:** every block of the paper's PyMuPDF block stream.
**Exits:** the table-typed subset. Prose, headings and figure captions leave here and are out of
scope for this funnel.
**Removal conditions:** none — this is a filter that *defines* the population, not a drop.

`[measured]` **160** across the 21 papers, identical in all three arms (`current`,
`pymupdf_tables`, `pymupdf4llm`). Identical by construction: `blocks_from_pdf_layout` reuses
`blocks_from_pdf`'s stream verbatim and only *adds* keys (module docstring, lines 6-10).

### A2. `grid_return` — **"a backend grid return"**

**One item:** one table block for which the layout backend supplied a non-`None` raw grid
(a `list[list[str]]`), assigned at lines 351-354.

Two tiers, decided **per table**:
- tier 1 `page.find_tables()` (`_tier1_grids`, line 232) — ruling-line tables;
- tier 2 `pymupdf4llm.to_markdown(..., table_strategy="text")` → markdown pipe tables
  (`_tier2_page_markdown` line 273, `_parse_pipe_tables` line 255) — borderless tables.

Table blocks on a page consume that page's grids **in reading order** by index (line 346-355).

**Enters:** 160 table blocks.
**Exits:** blocks that got a grid.
**Removal condition — exactly one:** `grid is None` → `table_fallback = "no_grid_from_backend"`
(line 386). Reason code **`NO_GRID_FROM_BACKEND`**. This fires when the page yielded fewer grids
than it has table blocks, i.e. the backend simply did not see a table there.

`[measured]` control arm: **18** dropped → **142 grid returns**. This is the brief's 142.
`[derived]` 160 − 18 = 142.

> In the `pymupdf_tables` arm this is **160 dropped → 0 grid returns**: `find_tables()` returned
> nothing on every one of the 160 tables. That arm's entire failure is at A2.

### B2. `binding_attempt` — entering the binder

**One item:** one call to `structural_bind(value, chunks)` (line 390), made from `_gate_value`
line 525-526.

**Entry guard, line 525:** `if _NUMVAL.search(value or "")`, where
`_NUMVAL = NUMERIC_ANCHOR_RE = re.compile(r"\d+\.\d+|\b\d{2,}\b")` (`src/evidence/anchors.py:27`).
A value with no decimal number and no 2+-digit integer **never enters the binder**. The harness

`[measured]` control: **8 of 22** claims are `no_binding_call` → **14 enter the binder**.
`[measured]` `value_failed_sanity_check` 0, `metric_value_out_of_range` 0.

**Reason code for the entry drop: `NO_NUMERIC_ANCHOR`** (`gate.py:525`, regex at `anchors.py:27`).

### B3. The binder's contract — what it compares

`structural_bind` (line 390). Decision order, verbatim from lines 393-417:

| # | condition | status |
|---|---|---|
| 1 | `paper_table_cells(chunks)` is empty — the paper has no cells at all | **`pdf_only`** |
| — | `_NUMVAL.findall(value)` is empty | `no_number` |
| 2 | claimed metric matches **no column** in any table of this paper | **`not_bindable`** |
| 3 | value found at the (subject-row × metric-column) cell | **`bound`** |
| 4 | value in the metric's column but at a **different row** | **`wrong_cell`** |
| 5a | value in **no cell of any table** | `not_a_table_claim` |
| 5b | value in some cell, but not under the metric's column | **`wrong_cell`** |

**Which fields it compares:**
- **claim side** — the raw `value` string. Numbers by `_NUMVAL.findall` (line 442). Metric tokens
  by `_metric_tokens(value)` (line 444, defined 294). Subject by `_SUBJECT_RE.match` (line 446,
  defined 266); an `_OWN_ROW` subject (line 263) collapses to `None` = the paper's own row
  (line 448-449).
- **cell side** — `column_header` via `_col_matches_metric` (line 322), `row_label` via
  `_row_matches_subject` (line 330), `value` via the nested `_has` (line 459).

**The comparison itself — `_has`, lines 459-465.** This is the whole of the value comparison:

```python
if n == re.sub(r"[^\d.\-]", "", s):        # strip to digits, dot, hyphen; exact equality
    return True
return bool(re.search(r"(?<![\d.])" + re.escape(n) + r"(?![\d])", s))   # token-boundary substring
```

There is **no numeric parsing and no unit handling**. The claim number `n` is compared as a
*string* against the cell string `s`. The `[^\d.\-]` strip is the only normalisation of the cell,
and **the claim side is never normalised at all**. Consequences, all structural:

- `−0.4` (U+2212 minus) does not reduce to `-0.4` — U+2212 is stripped entirely, giving `0.4`.
- `92.3 %` vs `92.3%` both reduce to `92.3` under the strip branch, so they match.
- `1.2 × 10^-4` vs `1.2e-4` cannot match under either branch.
- Bold markup surviving in a cell value is stripped by `[^\d.\-]` only if it is non-numeric.

**Raw vs normalized:** raw on the claim side, digit-stripped on the cell side. The two sides are
**not** normalised by the same rule. (Contrast `_metric_tokens`, which *was* deliberately made
symmetric across both sides — see `BINDING_VALIDATION_REPORT.md` F1. The value comparison never
received the same treatment.)

**ID formats:** cells carry no table label. `_layout_table_cells` builds `table_id` as
`f"{paper_id}:{cpath}"` (line 69) where `cpath` is the block id, and **the binder never reads
it**. `structural_bind` pools `paper_table_cells(chunks)` — every cell of every table in the
paper — into one flat list (line 433) and searches it without regard to which table a cell came
from. **A "(Table 1)" reference in a claim is therefore ignored entirely**: there is no table
resolution step anywhere in the path. `_table_type_for` (line 383) groups tables by caption string
equality only, and is consulted *after* binding, not during it.

### B4. `binding` — the success criterion

**A binding is successful iff `structural_bind` returns `status == "bound"`**, i.e. case 3:
some number `n` of the claim is `_has`-matched in a cell whose `column_header` matches the claim's
metric tokens **and** whose `row_label` matches the claim's subject.

That is the criterion the gate then acts on at line 536.

`[measured]` **`bound` = 0** in every arm, every paper, every claim. This has never fired in any
production-realistic measurement in this programme.

## 4. So what sits between 142 and 3?

Nothing does, because they are not on the same path. The brief offers "retrieval top-k, a score
threshold, a filter, dedup, or query dependence" as candidates. **None of those exist anywhere in
this path.** `[measured]` facts:

- There is **no retrieval** in the measured path. No Chroma query, no embedding, no top-k, no
  score threshold, no ranking. `run_one` calls `blocks_from_pdf_layout` → `chunk_document` →
  `gate_paper` and nothing else (`parser_backend_measure.py:137-166`).
- There is **no dedup** of grids, cells or claims.
- There is **no query**, so no query dependence. The claim set is read from a frozen cache.

The real answer is two independent collapses, quantified in report §5 and §6:

1. **142 → 92** is the quality gate plus the post-gate parse: 46 + 4 = 50 tables, every one
   attributed to a named condition in `_gate_grid` / `_layout_table_cells`.
2. **→ 3 → 0** is a different population entirely. Of the 22 claims, 8 never reach the binder
   (`NO_NUMERIC_ANCHOR`), 9 die at `pdf_only`, 3 at `not_bindable`, 2 at `wrong_cell`. The 3
   RETURNED metrics are `'F1-scores'`, `'F1 score'` and `'GPT-4-based metrics'` — **metric names
   containing no number at all**, which is precisely why they are RETURNED: they carry no numeric
   anchor, so the binding branch at line 525 is skipped and they fall straight through to
   grounding and attribution. **Zero of the 3 RETURNED results ever enter the binder.**
